# Repository Ontology

| Term | Meaning |
|---|---|
| Requirement | Stable statement of what the system must do |
| Design | How components satisfy requirements |
| Configuration | Changeable default or feature flag |
| Skill | Reusable capability with inputs, process, and completion criteria |
| Workflow | End-to-end orchestration of skills and gates |
| Worksheet Spec | Canonical structured source for a worksheet and its answer key |
| Run Manifest | State, provenance, approvals, QA, telemetry, and outputs for one run |
| Knowledge | Subject curriculum, progression, source metadata, and durable reference material |
| Template | Protected layout source copied before use |
| Output | Approved canonical worksheet or answer key |
| Staging output | Noncanonical intermediate artifact |
| Gate | Required human approval state when enabled |
| Confidence | `confirmed`, `strongly_inferred`, or `inferred` curriculum status |
